## 🌟 一、設計初衷與核心理念

### 1. 痛點發現
當我們在看 YouTube 學習做菜、烤甜點或編織繩結時，**雙手往往沾滿麵粉、握著刀鏟或拉著繩線**。
這時候如果遇到看不懂的步驟（例如：「麵糊要攪拌到什麼濃稠度？」、「繩子是從上面還是下面穿過？」、「辣椒到底是要冷油還是熱油下鍋？」）：
- **無法及時操作鍵盤滑鼠**：雙手很髒，無法隨意倒帶或暫停影片細看。
- **傳統影片無互動性**：市面上 90% 的 AI 工具僅能產生全片「文字摘要」，無法針對當下畫面中主廚的手勢或材料狀態即時提問。
- **字幕常常缺失或不全**：許多手作教學影片沒有字幕檔，對白字幕甚至直接壓印在畫面中。

### 2. 核心理念與解決方案
本專案的誕生，就是為了解決上述痛點：
- **以暫停當下為核心，真正看懂畫面**：影片暫停時，AI 自動分析連續動作影格（或由雲端視覺模型直讀視訊音軌），精準看懂動作與材質狀態。
- **語音對話，徹底解放雙手**：支援語音發問與語音朗讀，完全不必用沾滿麵粉的雙手碰觸鍵盤與螢幕。
- **時間軸歷史標記與點擊跳轉**：AI 回答附帶精準時間膠囊按鈕，影片進度軸上亦會以標記顯示歷史問答，隨點隨跳。
- **日／月雙模與極致視覺**：提供溫暖木質調深色模式與清新明亮模式，載入不閃爍，閱讀無負擔。
- **零隱私洩漏與成本受控**：伺服器不下載影片，截圖不永久留存，具備自主邀請名單與每日額度管理機制。

## 🏆 二、與市場競品之差異化優勢（核心技術亮點）

經過深度市場競品調研（涵蓋 YouTube 官方 Ask、市售擴充功能、料理專用 App 及通用筆記摘要軟體），本專案具備不可替代的獨特技術實踐：

| 評估面向 | 市售多數競品 (NoteGPT / Eightify / 擴充功能) | YouTube 官方 Ask 功能 | **本專案 (YouTube AI 學習助手)** |
|---|---|---|---|
| **分析核心依據** | 僅讀取整部影片的「字幕文字」，完全不看畫面 | 逐步測試中，偏全片摘要 | **以暫停點為中心，真正看懂動作畫面與畫面上壓印字卡** |
| **目標場景定位** | 通用文字摘要、讀書筆記 | 通用影片問答 | **專注於料理、烘焙、編織手作等「動手做」高視覺領域** |
| **繁體中文支援** | 各家表現不一，需額外提示詞 | 尚未開放台灣與繁體中文 | **原生繁體中文優先設計，回答語言隨使用者動態調整** |
| **軟體形態** | 僅有擴充功能或僅有網頁版 | 僅限特定網頁/電視版 | **網頁版（手機可用）＋ Chrome 擴充功能，帳號與紀錄全同步** |
| **權限控管架構** | 封閉式商用系統 | 依官方帳號權限 | **自建邀請名單白名單資料庫，杜絕未授權存取** |
| **私有化彈性** | 完全依賴第三方雲端封閉平台 | Google 封閉生態系 | **支援 Docker 容器化私有部署（群暉 NAS），可獨立營運** |

## 🚀 三、系統架構展示

```
YouTube AI 學習助手
├── 前端 (Frontend)
│   ├── Chrome 擴充功能 (Manifest V3)：固定金鑰 ID，內建語音辨識、影格截取、深色/明亮雙模
│   └── 跨平台網頁版 (Web App)：精美排版、影片時間軸提問標記、膠囊跳轉按鈕、手機完全相容
└── 後端 (Backend)
    ├── 核心框架：Python FastAPI (高效非同步服務，支援反向代理與容器化)
    ├── 資料庫：SQLite (app.db，管理使用者、邀請名單、每日配額、問答歷史)
    ├── 認證系統：Google OAuth 2.0 (結合後端自建邀請白名單，非名單成員禁止存取)
    ├── 智慧路由：ai_router.py (主力多模態模型自動容錯切換、Token 與思考模式限制)
    └── 部署環境：Docker Compose 容器化部署（群暉 NAS 閘道反向代理）
```

## 📈 四、版本演進史歷程總覽

本專案歷經扎實的實測與快速反覆運算，走過多個主要發展里程碑：

| 階段與版本號 | 核心功能突破與重要改進 |
|---|---|
| **第 0 階段 (phase0)** | 人工實測傘繩、烘焙、烹飪影片，確立「暫停前 12 秒至當下共 5 張影格，不往後跳」的擷取機制，驗證多模態判讀可行性。 |
| **v1.0 ~ v1.4** | 推出 Chrome 擴充功能 MVP，搭配本機開源視覺模型；全面實測本機顯卡算力，摸清消費級硬體不足以負擔連續圖文即時推論，決定轉型。 |
| **v2.0 ~ v2.2** | 全面轉向雲端多模態 API 路由架構，將回應時間縮短至 3~7 秒；修復思考模式溢出截斷問題，加入連網查證來源標記與本機歷史紀錄匯回。 |
| **v3.0 ~ v3.1.2** | 完成 NAS Docker 部署、Google 登入系統與免安裝網頁版；視覺重構為深色木質調、新增影片時間軸標記、大頭貼破圖修正與日／月切換雙主題。 |
| **v3.2** | 擴充功能與網頁版全面打通！共用同一個 NAS 後端、同一個 Google 帳號與跨裝置同步問答紀錄；統一外觀風格。 |
| **v3.3 (最新版)** | 實作「自建受邀白名單管理機制」，解決 Google 測試模式無法阻擋未受邀登入的漏洞，管理者可在後台隨時管理邀請名單。 |

## 💻 五、技術堆疊與實作元件

### 1. 後端 (Backend)
- **FastAPI**：高效非同步框架，實作影片資訊提取、智慧路由排程與身分驗證。
- **SQLite (accounts.py)**：安全儲存憑證雜湊、邀請白名單、每日配額計數與跨平台問答歷史。
- **多模型智慧路由 (ai_router.py)**：動態整合 Google Gemini 等多模態視覺模型，具備自動容錯換線、思考長度抑制與即時連網驗證機制。
- **Docker Compose**：容器化打包與反向代理整合，已於群暉 NAS 成功完成部署實踐。

### 2. 前端 (Frontend)
- **Chrome 擴充功能**：Vue 3 + Vite + TypeScript (Manifest V3)，具備影片影格背景捕獲、字幕封包攔截、原生語音辨識與朗讀。
- **跨平台網頁版**：模組化 HTML5/CSS3/JavaScript，自適應深淺雙主題、自適應響應式排版（手機/桌機全相容）與自訂播放時間軸標記。

## 🔒 六、隱私安全與資料政策設計

1. **嚴密金鑰隔離**：所有 API Key 與敏感憑證皆純伺服器端環境變數隔離，前端與擴充功能代碼不含任何機密。
2. **無原始視訊留存**：視訊畫面僅於記憶體中即時推論，不寫入任何伺服器硬碟，杜絕版權與隱私風險。
3. **白名單防護機制**：內建邀請名單過濾，未獲邀請之帳號無法使用系統資源，確保每日配額安全。
4. **資料自主權**：使用者可隨時匯出自己的全部問答紀錄，或一鍵從伺服器徹底刪除個人歷史資料。
